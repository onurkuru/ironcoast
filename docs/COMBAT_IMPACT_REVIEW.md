# Combat impact, landing and synchronized audio review

This phase refines the workshop and Ironline review encounters while new guard
locomotion art remains pending. It creates no character artwork and retains the
approved environment, sprites, weapon sounds and music.

## Visible changes

A guard hit previously emitted localized particles, a second weapon impact,
a generic collision burst, and an additional ten-square burst when lethal.
Those overlapping effects obscured the reaction pose. In the two cinematic
review scenes, a guard impact now emits four short armor spark streaks. The
generic guard collision/death bursts are suppressed; other campaign effects
retain their previous behavior.

Sparks have bounded tails, drag and floor clipping. The eight-pose collapse
triggers one landing event as it reaches the hip-contact frame. Five small,
low-opacity dust puffs stay above the registered ground line and dissipate.
The effect uses the same monotonic collapse offset as the body. It does not
repeat during the corpse hold/fade or overwrite live particles when the pool
is full.

The landing has a new short, low-frequency synthesized thud with noise and a
decaying amplitude. It attenuates with listener distance. This is a new event
cue, not a replacement of the full sound library or a recorded Foley asset.

## Files

- `data/presentation.json`, `tools/compile_presentation.py`,
  `src/presentation_config.h`: one source for all new effect/audio tuning.
- `src/game.h`: named particle types, contact plane, one-shot landing state and audio event.
- `src/game.cpp`: remove duplicate review effects, integrate bounded particles,
  and trigger the landing at the collapse contact phase.
- `src/weapon_effects.cpp`: pooled armor sparks and landing dust.
- `src/render.cpp`: short streaks and restrained floor-bound dust drawing.
- `src/audio.h`, `src/audio.cpp`: landing synthesis and offline access to the same SDL mixer.
- `src/main.cpp`: `--record-audio` capture with exact sample scheduling.
- `tests/test_guard_impact.cpp`, `tests/test_audio.cpp`, `CMakeLists.txt`:
  projectile-path effects, timing, pool saturation, floor bounds and audio checks.

No PNG or external sound asset is created. Effects use the existing SDL drawing
and audio systems; they add no shader dependency or audio-library requirement.

## Configuration

All new values are in `data/presentation.json` under `guardImpact`.

| Keys | Defaults | Meaning |
| --- | --- | --- |
| sparkCount / sparkLife | 4 / 0.16 s | Per-hit budget and lifespan |
| sparkSpeed / sparkGravity | 46 / 120 | Initial motion and downward acceleration |
| sparkTrailTime / sparkTrailMax | 0.022 s / 2.5 | Streak length limits |
| sparkColor | DEB985FF | Warm armor impact tint |
| landingPhase | 0.62 | Normalized collapse time for ground-contact event |
| dustCount / dustLife | 5 / 0.32 s | Landing dust budget and lifespan |
| dustSpeed / dustLift | 18 / 7 | Lateral spread and upward motion |
| dustSize / dustOpacity | 3.5 / 24 | Soft puff radius and opacity cap |
| dustColor / drag | 87999EFF / 6 | Dust tint and velocity decay |
| landingFrequency / landingPitchDrop | 92 / -135 | Initial Hz and Hz per second |
| landingDuration / landingGain | 0.18 s / 0.19 | Cue duration and volume |
| landingNoise / landingDecay | 0.15 / 22 | Noise mixture and exponential decay |

Recompile `src/presentation_config.h` and rebuild after tuning changes. Existing
`guardReactions` values continue to control the collapse itself. Existing
`audio.falloff` controls distance attenuation.

## Test and capture

From the recovery worktree:

```sh
python3 tools/compile_presentation.py
cmake --build ../../work/build-cinematic-review -j4
ctest --test-dir ../../work/build-cinematic-review --output-on-failure
mkdir -p ../../work/combat-impact-v4-frames
SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy \
  ../../work/build-cinematic-review/kiyi_hurdasi --assets assets \
  --guard-action-review --frames 540 --fast \
  --record ../../work/combat-impact-v4-frames --record-every 1 \
  --record-audio ../Target-Recovery-Review/combat-impact-v4.s16le
```

The existing automated combat sequence shows a sentry approaching and firing,
then the player returning fire. The audio is generated by the game's own mixer,
including current music, shots and the new landing cue. Offline audio capture
requires `--fast` and a positive frame limit, opens no playback device, and writes
32kHz mono signed 16-bit little-endian PCM. It schedules 533/534 samples per
60fps frame using integer totals so a nine-second video has exactly 288,000
audio samples. This avoids wall-clock recording drift and callback races.

Mux the result from the review output directory:

```sh
ffmpeg -framerate 60 -i ../../work/combat-impact-v4-frames/frame%05d.png \
  -f s16le -ar 32000 -ac 1 -i combat-impact-v4.s16le \
  -c:v libx264 -crf 18 -pix_fmt yuv420p -c:a aac -b:a 128k \
  -movflags +faststart -shortest combat-impact-v4-av.mp4
```

Compare the lethal hit to `guard-action-v3-60fps.mp4`: the guard should remain
readable instead of disappearing behind cream-colored squares. Check the small
ground puff and low thud at body contact. This is an offline engine capture,
not a Vita performance benchmark or a claim that all audio is final.

Interactive review still uses `Play Workshop.command` and `Play Ironline.command`.
The main checkout and published releases are unchanged.

## Validation result

All thirteen CTest suites passed on the development Mac. The new effect test
fires a real projectile and checks that only the budgeted spark group appears,
that the landing is emitted once at the contact phase, that particles expire
and stay above the floor, and that a saturated pool preserves active particles.
Audio tests cover the landing cue's distance attenuation and verify that
frame-sized offline chunks produce exactly the same samples as a continuous
mixer call.

The recorded PCM contains exactly 288,000 samples (nine seconds at 32kHz), peak
amplitude 10,500 and no samples at the signed 16-bit clipping limit. The video
contains 540 frames. Visual inspection of the lethal hit and settled body
confirmed that the former large square death burst is absent. These are
technical checks, not a claim that the soundtrack or character art is final.
